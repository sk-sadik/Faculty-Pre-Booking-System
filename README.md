# Faculty Pre-Booking System — COMPLETE

Students view faculty availability, book appointments in advance, and track
status. Faculty manage availability and handle requests. Admins manage users,
departments, analytics and demo data. Flutter + Material 3, Riverpod,
go_router, Firebase (Auth + Firestore + Messaging).

## Setup & run

1. Create a Firebase project, enable **Authentication → Email/Password**,
   create a **Cloud Firestore** database.
2. `dart pub global activate flutterfire_cli`
3. `flutterfire configure --project=<your-project-id>` (regenerates
   `lib/firebase_options.dart`; puts `google-services.json` in
   `android/app/` — `minSdk` is pinned to 23 and the google-services
   plugin is already wired).
4. Deploy rules + indexes:
   ```powershell
   firebase deploy --only firestore:rules
   firebase deploy --only firestore:indexes
   ```
5. ```powershell
   flutter pub get
   flutter run
   ```

Make your first admin: register a user in-app, then set
`users/{uid}.role = "admin"` in the console and sign in again. Or run the
seeder (below) and promote one of the demo accounts.

## Troubleshooting

- **"No Firebase App '[DEFAULT]' has been created"**: `flutterfire
  configure` not run, or `google-services.json` /
  `GoogleService-Info.plist` missing. The app shows a setup screen with
  steps (`FirebaseSetupErrorScreen`) instead of crashing.
- **Android google-services failure**: package name must match
  `com.faculty.prebooking.faculty_pre_booking`.
- **"Profile not found" after login**: Auth user exists but `users/{uid}`
  is missing — re-register in-app or ask an admin.
- **Push not arriving**: inbox notifications always work (Firestore);
  FCM needs a real device + configured Firebase project. Token sync is
  best-effort and silent on failure.
- **Removing a user (admin)**: deletes the Firestore profile; delete the
  Auth account in the Firebase console too.
- **"Demo data already seeded"**: delete `seed_meta/demo_v1` to re-run.

  `presentation/screens/register_screen.dart`, `data/repositories/auth_repository_impl.dart`
- Login with role-based redirect guard — `login_screen.dart`, `core/router/app_router.dart`
- Forgot password, logout, persistent session, friendly errors —
  `forgot_password_screen.dart`, `profile_screen.dart`, `core/errors/failures.dart`
- Profile/settings incl. theme — `profile_screen.dart`

### Student (`features/student`, `features/appointments`, `features/users`)
- Home: upcoming, stats, shortcuts — `student/.../student_home_screen.dart`
- Directory: search + department + available-today — `faculty_directory_screen.dart` (+ `slot_providers.dart`)
- Faculty detail: profile, cabin, weekly hours, 14-day strip, free-slots-only picker — `faculty_detail_screen.dart`
- Booking form (purpose/note, stale-slot recheck) + confirmation — `booking_form_screen.dart`, `booking_confirmation_screen.dart`
- My Bookings 6 tabs — `my_bookings_screen.dart`
- Booking detail: tracker, cancel (2h cutoff), accept/decline proposal — `appointments/.../booking_detail_screen.dart`
- Notifications inbox + badge — `notifications/.../notifications_screen.dart`

### Faculty (`features/faculty`, `features/availability`)
- Home: today's schedule, pending count, Available-now toggle — `faculty_home_screen.dart`
- Inbox: Pending/Proposed/History — `requests_inbox_screen.dart`

- Availability: weekly/one-off/blocked CRUD — `manage_availability_screen.dart`, `rule_editor_sheet.dart`
- Calendar (table_calendar + agenda) — `faculty_calendar_screen.dart`
- Booking settings (max/day, buffer) — `faculty_settings_screen.dart`

### Data & rules (Phase B)
